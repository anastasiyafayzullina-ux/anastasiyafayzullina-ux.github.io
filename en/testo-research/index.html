Testo User Research

I studied user behavior, found pain points, formed and tested hypotheses, then estimated and prioritized improvements with the dev team and moved the top ones into development.

About the project

Testo is a News Media Holding platform for creating and publishing interactive content.

In 2 years, it grew from an MVP into a full-fledged product. We shipped many features and greatly expanded its functionality. Now we needed to understand where to go next and find growth opportunities.

Goals

Here’s what we wanted to achieve:

Identify priority features

This helps focus development on the features users value most

Improve the user experience

Use feedback to find problems and improve how people interact with the platform, making tasks faster and easier and raising overall user satisfaction

Analyze behavior patterns

Study how employees use the platform day to day, so the interface logic fits their real tasks

Research plan

The work was split into 4 stages.

Stage 1: Setting up session recordings

Webvisor, the session replay tool in Yandex Metrica, would show us user behavior patterns: how exactly people use the platform, how long it takes to reach their goal (the goal: publishing a piece of interactive content), where they run into problems, and which interface elements they use and which they ignore.

Stage 2: Forming hypotheses

Based on the recordings, form hypotheses on how to improve the experience so users reach their goal faster and more easily.

Stage 3: User survey

This is how we test the hypotheses: ask users about usability, the features they use most, and the problems they face.

Also ask them to rate the platform on a 5-point scale (we plan to repeat the survey 6–12 months after the improvements). This score becomes a user satisfaction benchmark we can compare against later.

Stage 4: Improvements

Analyze all the data (from the survey and the recordings) and find out which hypotheses were confirmed.

Discuss all ideas and options with the dev team, and ship improvements within the team’s capacity.

Session recordings

We watched recorded user sessions. At first it wasn’t clear what to look for, so we built a table to log the key parameters:

Order of filling in content

What users fill in first: general info, or they jump straight to the questions

Behavior and pain points

Whether they uploaded media, used the preview, where they got stuck and couldn’t move on, and so on

Bugs

Errors or layout issues on different devices

Time

Session length and time to reach the goal

General info

OS, device type, browser

After 4–5 sessions, common patterns started to emerge. After watching 30 sessions, we formed our hypotheses.

Observation #1

After uploading images, most users open the preview to check how the image was cropped. If they don’t like it, they delete it, crop it in a third-party tool and upload it again

Hypothesis #1

If we add an image editor, users will work faster and handling images will become easier

Observation #2

Some users get confused when setting score ranges on the Results tab: some scores fall into two ranges at once, and others into none

Hypothesis #2

If we auto-fill the minimum score (still editable), users will get confused less

Observation #3

A common scenario in quizzes: users put the same content into the Subtitle and Media fields of every intermediate result, copying and pasting it several times

Hypothesis #3

If users can apply the Subtitle and Media content to all intermediate results at once, filling in a quiz will take less time

Survey

It had 15 questions and, by our estimate, took 5–10 minutes. We ran it online with Yandex Forms. Here you can see a copy of the survey (in Russian) (all fields are optional for convenience).

28 respondents took part: colleagues from different newsrooms who use the platform to varying degrees.

We collected all answers in one table. Below is a part of it for 10 respondents, which reflects the overall results.

We rated how critical each comment was based on its impact on completing the scenario.

  • 1Critical issues — may prevent users from completing the scenario
  • 1Non-critical issues — don’t affect completing the scenario
  • 1Feature requests

We gathered the comments in a separate table and came up with solutions together with the team. Below is a part of it for 8 comments.

2“You can’t remove an answer’s +1 link to a result — for example, if you added it by mistake and want to undo it”Add a “Not selected” option to the dropdown
3“Automatic image cropping (right now images in a different format look odd), and the option to crop an image manually right when uploading it”Add an image editor

Improvements

2 hypotheses were fully confirmed, and 1 was partially confirmed:

Hypothesis #1

If we add an image editor, users will work faster and handling images will become easier

Confirmed

Half of the users said they were missing image cropping (question #12 and comments)

Hypothesis #2

If we auto-fill the minimum score (still editable), users will get confused less

Partially confirmed

The survey shows that some users don’t understand how to set scores (question #3)

Hypothesis #3

If users can apply the Subtitle and Media content to all intermediate results at once, filling in a quiz will take less time

Confirmed

About 40% of users reported frustration with typing the same text manually several times (question #13 and comments)

We went through all the findings from the recordings and the survey with the dev team and set priorities. For the first stage, the team had capacity for these improvements:

Hypothesis #1

Design an image editor

Hypothesis #2

Auto-fill the minimum score (still editable)

Critical issues

Add a “Not selected” option to the dropdown in advanced tests

Non-critical issues

Raise the character limit for media captions

Bugs

Fix the media upload bug (request error 400)

Widget improvement

Add a Share button to the widget’s final screen

We left the rest for later: these are good growth opportunities, but there was no capacity to build them yet.

Hypothesis #3

A complex change that would likely require rewriting the quiz logic

Working with images

“I’d like to upload all the images I’ll need at once and then pick them while filling in the content” — a user insight

Templates

“I’d like more color templates for tests, quizzes and polls (for example, a light theme like crosswords have)” — a user insight

We also learned which features users rarely or never use: the copy-link button and the created/edited dates on content cards, and advanced tests.

The most used filter is Employee, but about 70% of users don’t use filters at all.

If needed, these can be rethought or removed in the future.

Final design

Here’s how it all came together.

We designed an image editor that lets users crop images to the right format right in the platform.

We added auto-fill for the minimum score on the Results tab (still editable), making score ranges easier to set.

We added sharing to the results screen to encourage people to share their results.

Results

As a result of the research, we:

Identified behavior patterns

How long it takes to create and publish content, where users struggle, and which features are used actively and which are ignored

Confirmed 2 of 3 hypotheses

The third was partially confirmed

Shipped improvements

They improve the key user scenarios

Measured user satisfaction

4.5 out of 5. We plan to repeat the survey in a year to measure the effect of the changes

Built an improvement backlog

Some of the items are already in development

Added new engagement points

Sharing results became one of the ways to increase engagement

After the improvements, routine support requests became less frequent.

It’s too early for quantitative metrics. We plan to track the key ones: time to complete key scenarios, return visits, support requests and user satisfaction.
