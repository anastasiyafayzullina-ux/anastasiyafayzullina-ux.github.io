Testo Interactive Content Platform

A News Media Holding platform for creating and publishing interactive content: quizzes, tests, polls and crosswords.

About the project

Online quizzes have become increasingly popular. They are a way to express yourself and connect: people send quizzes to each other and share their results. On news websites, they also improve key metrics: session time, page views and pages per session.

Why did we need Testo? Before it, each newsroom created quizzes and polls in its own separate admin panel. Every new feature had to be built several times, which wasted development resources and kept the functionality limited.

Goals:

/ 01

Give users faster access to new features through a single platform

/ 02

Cut development costs by eliminating duplicate work

/ 03

Increase audience engagement with new interactive formats

Tasks:

/ 01

Design a convenient, easy-to-understand tool for creating interactive content.

/ 02

Create a responsive widget that embeds correctly into every newsroom’s website.

Research

Competitive analysis

We started by analyzing competitors and singled out Madtest and Kahoot: their features and visuals were the closest to our requirements.

We looked at both the admin panel (how interactive content is created) and the website widget (what users see).

Next, we reviewed the existing solutions within our holding. Each newsroom had its own admin panel, and each implemented polls and quizzes differently.

There were two approaches: all questions stacked on one page, or a slider of questions. Both had one big drawback: it’s hard to find your way around when there are many questions.

Target audience

Journalists and editors who write all the content for the newsrooms. Here’s what we know about them:

They want to create content quickly and easily

The constant news flow takes up all their time

They know how admin panels work and are comfortable using them

They are familiar with the interface and its basic elements

They usually work in the desktop version of the admin panel

The mobile version is mostly used for breaking news

JTBD and hypotheses

We analyzed what we had learned and the feedback from newsrooms, wrote down the jobs to be done, and built hypotheses on top of them.

JTBD

Hypothesis

/ 01

When I publish interactive content, I want to track its results, so I can see which formats take off

/ 01

If we add a Statistics section, editors will be able to analyze how interactive content performs and repeat what works

/ 02

When I finish a quiz, I want to quickly review all the questions, so I can be sure there are no mistakes

/ 02

If we add a preview, editors will catch mistakes in advance, which will reduce fixes after publishing

/ 03

When I open the platform, I want to quickly find my piece among all the others, so I can continue working on it

/ 03

If we color-code content by type, editors will tell items apart faster, which will cut search time

/ 04

When I create a quiz, I want to see all the settings on screen, so I can switch between them quickly without losing context

/ 04

If we add a sidebar, editors won’t lose context and will be able to make changes faster

UX design

User Flow

We built the platform in two stages: an MVP, and then growing it into a full-fledged product.

The MVP needed the core features: creating and editing tests, quizzes and polls. Later, we added new sections (Statistics, Projects, Employees, Roles), new content types (crosswords and advanced tests) and new features (restoring deleted items, templates, a timer and more).
